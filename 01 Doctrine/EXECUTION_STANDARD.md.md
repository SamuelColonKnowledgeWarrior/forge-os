# EXECUTION STANDARD

## Purpose

Define the minimum quality standard for every build produced within the Forge Operating System.

## Core Principles

1. Artifact First  
    Every work session ends with a deployable artifact whenever possible.
    
2. Finish Before Expand  
    Complete active work before creating new initiatives.
    
3. Audit Before Build  
    Review existing assets before creating new files or structures.
    
4. Single Source of Truth  
    Command files govern execution. Avoid duplicate or conflicting information.
    
5. Execution Over Discussion  
    Prioritize shipping completed work over explaining plans.
    

## Build Checklist

Every build should:

- Have a clear objective
    
- Be production-ready
    
- Fit existing doctrine
    
- Avoid placeholders unless requested
    
- Update continuity documents when applicable
    

## Standard Deliverable

- Mission Status
    
- Completed Artifact
    
- Deployment Location
    
- Next Build
    

## Definition of Done

A build is complete when:

- The artifact is finished
    
- It can be deployed immediately
    
- It advances the active mission
    
- No critical placeholders remain
    

## Motto

Build. Ship. Continue.
